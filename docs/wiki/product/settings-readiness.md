# 设置页创作可用性原则

## Background

系统设置页承载模型厂商、模型路由、知识库、写法引擎、自动导演授权和桌面维护等能力。对于完整写作新手来说，这些配置如果按技术模块平铺，会让用户误以为必须理解所有参数后才能开始写小说。

设置页的首要任务不是展示所有参数，而是回答用户最关心的问题：现在能不能开始创作，如果不能，还差哪一步。

## Decision

设置页以“创作可用性检查”作为首屏核心信息。页面应先展示开始创作所需的模型和路由状态，再展示知识库、写法引擎、自动导演高级设置和系统维护。

知识库、写法引擎和通知通道属于增强或高级能力，不能在视觉和文案上阻塞用户开始创作。模型厂商详情默认降噪，只展示可用状态、当前模型、余额摘要和主操作；技术参数进入高级详情。

## Current Rule

- 首屏必须清楚说明基础创作链路是否可用。
- 缺少正文模型时，引导用户先配置模型厂商。
- 模型路由异常时，引导用户进入模型路由管理。
- 知识库未启用时，明确说明这是可选增强，不阻塞创作。
- 写法引擎用“快速检测 / 稳定推荐 / 长文提取”这类用户任务语言表达，分钟数保留在高级设置。
- 审批授权、导演跟进通道、桌面维护不应占据开始创作前的主要注意力。

## 模型设置快捷入口一致性

顶栏「模型设置」弹窗与系统设置「模型与厂商」是同一配置能力的两个入口，不是两套配置。弹窗承担快捷入口职责：用户在弹窗里就能完成厂商选择、凭据填写、模型选择与保存，不需要为了配齐生图能力再跳进系统设置。

- 文本模型：选择厂商 → 连接模型 → 检测完成（含连通性测试）。
- 生图模型：与「模型与厂商」同构 —— 列出所有可生图厂商（含未配置的，显示「可用 / 待配置」与当前生图模型），点开厂商卡片填写 API Key / API 地址 / 生图模型，也支持添加第三方 OpenAI 兼容厂商。
- 仅生图厂商没有文本连通性测试入口，保存即视为完成配置。
- 未配置厂商在弹窗内补齐凭据后保存会直接激活，不需要回设置页二次启用。

实现约束：两处共用 `client/src/pages/settings/components/providers` 下的 `useProviderConfigFlow` 与 `ProviderConfigDialog`。新增厂商配置能力（新字段、新校验、新厂商形态、新引导步骤）必须落在这套共用实现里；禁止在弹窗或设置页内另写一条配置流程，避免两个入口行为分叉。

## Failure Modes

- 如果设置页再次变成厂商、API 地址、模型标签和运行参数的长列表，新手会难以判断下一步，容易放弃开书。
- 如果模型设置弹窗只支持「挑一个已有厂商 + 换个模型」，用户会被迫在配置不全时跳去系统设置，快捷入口名不副实。
- 如果弹窗和设置页各维护一份厂商表单，同一字段的校验、默认值和保存行为会逐渐分叉。
- 如果知识库或写法引擎文案暗示“必须先配置”，用户会把增强能力误解为创作前置条件。
- 如果模型路由异常只显示在模型路由页，设置页无法承担全局创作入口的诊断职责。
